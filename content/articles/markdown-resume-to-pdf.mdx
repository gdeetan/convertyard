Almost every resume tool follows the same pattern: drag boxes around, pick from a small set of themes, save your work behind an account, pay to remove a watermark. That works for people who write a resume every few years. For people who update theirs quarterly — developers, freelancers, consultants — it is a bad tool.

The version-controlled alternative is Markdown. A resume in a `.md` file, tracked in git, rendered to PDF on demand. This is how most senior engineers keep theirs these days, and once you switch, it is difficult to imagine going back.

## Why Markdown beats resume builders for iterating

The resume is a document you edit constantly:

- New role starts → update the experience section.
- Applying to a full-stack role → add a portfolio link near the top.
- Applying to an infra role → drop the frontend paragraph, emphasize the infrastructure work.
- Updating your headline for LinkedIn → change the summary line.

Every one of those edits is a text change. In a drag-and-drop builder, each one takes a minute or two of clicking through UI. In a Markdown file, it is a five-second edit and a version-control commit that leaves a clean history of what you changed and when.

The other advantage: your resume is now text you can grep, diff, and search — the same tools you use for code. Every past version is a `git log` away.

## Formatting rules that keep resumes ATS-friendly

Applicant tracking systems (ATS) parse resumes into structured data before a human sees them. What breaks ATS parsers is not Markdown — it is layout tricks.

**Stick to a single column.** Two-column resumes look modern but confuse parsers. Since Markdown resumes are naturally single-column, this is a benefit you get for free.

**Do not put important content inside tables.** Tables render beautifully in the PDF, but many ATS systems read left-to-right across rows instead of understanding cells. Keep tables for skills matrices or comparison sections that are optional; put your experience in headings + bullets.

**Use standard section names.** `Experience`, `Education`, `Skills`, `Projects`. Cute headings like "The Story So Far" or "What Fires Me Up" get flagged as unclassified content by parsers that key off common labels.

**Bullet points, not paragraphs.** Every ATS handles bullet lists. Long paragraphs get chunked awkwardly.

**Selectable text, not screenshots.** ConvertYard generates text-based PDFs, not rasterized images. This is a hard requirement for ATS parsing — a resume that is technically a JPEG inside a PDF wrapper reads as a blank document to most parsers.

## Version control makes tailoring effortless

The workflow that beats every resume builder:

```bash
git clone git@github.com:you/resume.git
cd resume

# Master template
cat resume.md

# Create a role-specific variant
cp resume.md resume-fullstack.md
# Edit the summary + reorder projects to emphasize frontend work

# Commit the variant
git add resume-fullstack.md
git commit -m "Tailor resume for full-stack roles"

# Convert to PDF via ConvertYard
# (Drop the file into the browser, download the PDF)
```

Every variant is a first-class file. When you send an application, you can also commit which version you sent and to whom — so months later, you can regenerate the exact PDF a specific recruiter saw.

## What about design?

The honest answer: for engineering resumes, design mostly does not matter as long as the resume is clean, readable, and organized. Recruiters spend an average of six seconds on the first pass. What they are scanning for is your current role, your last role, and one or two keywords that match the job. Fancy layouts do not help with any of that.

If you want a more designed look, pick the Classic theme for a book-styled resume, or use the Modern theme with a subtle accent color. Both look professional; both are ATS-friendly.

## A note on privacy

Your resume contains your full name, current employer, home city, direct contact information, and a decade of work history. That is a document worth keeping off third-party servers when possible.

Most online resume tools upload every character you type to their servers for storage and processing. ConvertYard does not — the entire conversion runs in your browser via WebAssembly. Your resume text and the generated PDF exist only on your machine. If you write from a coffee shop, disconnect from Wi-Fi after the page loads and the tool still works.

For consultants and job-seekers currently employed, that matters. You don't need your current employer's SIEM flagging that you uploaded a file to a resume site.
