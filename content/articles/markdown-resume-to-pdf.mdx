Resume building tools on the web all work similarly – after you create your resume in a set of **rectangular blocks**, you can select from a number of themes and save your resume online after creating an account. Many of these tools require a **fee to remove a watermark** from printed copies. These tools are good for people who only create a resume every few years. For people who create and update resumes on a **quarterly basis** (programmers, freelancers, etc.), these tools are worthless.

The **version-controlled alternative** is called [Markdown](/markdown-to-pdf/) (as a resume in a `.md` file, tracked in git and rendered to PDF on demand as needed). This is how senior engineers keep their resumes these days. Once you've made the switch, it's hard to imagine going back to the alternative.

## Why Markdown beats resume builders for iterating

The resume is a document you edit constantly:

- New role starts → update the experience section.
- Applying to a full-stack role → add a portfolio link near the top.
- Applying to an infra role → **remove frontend-related paragraphs** and focus on infrastructure experience instead.
- Updating your headline for LinkedIn → change the summary line.

Each of these minor changes is **far faster as a text edit** in a Markdown file than clicking around in a drag-and-drop interface, and you can then make a **version-control commit** to keep a clean history of changes to your resume.

As an added bonus, your resume is now text that you can **grep, search, and even diff** – just like your code! All past versions are a `git log` away.

## Formatting rules that keep resumes ATS-friendly

Most **applicant tracking systems** first parse your application into structured data before a human even looks at it. While Markdown rendering on resumes can be problematic in some cases, most problems with ATS come from **really weird application layout**.

**Stick to a single column.** Two-column resumes look high-end these days. But ATS are generally stuck processing **single-column resumes**. Since Markdown resumes are automatically single column, this is a benefit to you.

Try to **avoid placing important content within tables**, as many ATS systems read content from left to right within a table row and do not 'read' individual table cells. Tables work best for **skills matrices or comparison tables**, which you can make optional, with experience outlined in section headings and bullet points instead.

Stick to **common section headers** like `Experience`, `Education`, `Skills`, and `Projects`. Avoid creative ones like "The Story So Far" or "What Fires Me Up," as these get treated as **unclassified content** by the parsing engines that look for common section names.

Rather than creating long paragraphs of text, **use bullet points**. That's how every ATS handles text. Long paragraphs of text get 'chunked' badly.

Note that a resume that is technically a **JPEG inside a PDF wrapper** reads as a blank document when fed to an ATS. ConvertYard outputs **text-based PDFs**. Selectable text in a PDF is a hard requirement for such a resume not to suck.

## Version control makes tailoring effortless

The workflow that beats every resume builder:

```bash
git clone git@github.com:you/resume.git
cd resume

# Master template
cat resume.md

# Create a role-specific variant
cp resume.md resume-fullstack.md
# Edit the summary + reorder projects to emphasize frontend work

# Commit the variant
git add resume-fullstack.md
git commit -m "Tailor resume for full-stack roles"

# Convert to PDF via ConvertYard
# (Drop the file into the browser, download the PDF)
```

Every variant is a first-class file. When you send an application, you can also commit which version you sent and to whom — so months later, you can regenerate the exact PDF a specific recruiter saw.

## What about design?

Design is a relatively **small concern** when it comes to engineering resumes. As long as your resume is **clean, readable, and organized**, that's all that matters. Typically, a recruiter spends only an average of **6 seconds** on the first pass through your resume. When scanning for current and past jobs, as well as a few keywords relevant to the position being advertised, fancy layouts just won't help.

If you want more design, the **Classic theme** creates a book-like resume, or you can choose **Modern** and add a subtle accent color. Both will look great and are also ATS-friendly.

## A note on privacy

Your **full name, current employer, home city, direct contact information**, and a decade of or more work history are all included in your resume. Keep that on **offsite servers** when possible.

A typical online resume builder uploads **every character you type** to their servers to store and process. In contrast, all ConvertYard resume conversions are run **completely in your browser via WebAssembly**. This means all created resume text as well as generated PDFs are **completely self-contained on your local machine only**. Thus, you can write up your resume in a coffee shop and have it all self-contained on your local machine – even when you're **disconnected from Wi-Fi** after the page has loaded.

For consultants and **currently employed job-seekers**, this means no upload of a file to a resume site to have your current employer's **SIEM flag it**.
