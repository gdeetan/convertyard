AVIF is the **AV1 Image File Format**, and it provides the **best compression of all commonly used web image formats**. However, until recently, browser support for AVIF was lagging behind that of WebP, and therefore its use was often complicated by the need to provide extensive fallbacks. **In 2026, that is no longer the case.**

## How to serve AVIF with a fallback

The standard method to deliver AVIF images to browsers that support them, and WebP or JPEG images to browsers that don't, is to use the HTML `<picture>` element.

```html
<picture>
  <source srcset="image.avif" type="image/avif">
  <source srcset="image.webp" type="image/webp">
  <img src="image.jpg" alt="Description">
</picture>
```

The browser reads the `<source>` elements **in order** and uses the first source element that it supports to render the image. So, for example, a browser that supports AVIF will get `image.avif`, a browser that supports WebP but not AVIF will get `image.webp`, and anything else will get `image.jpg`.

For most new projects in 2026, a **two-layer fallback (AVIF + JPEG)** is adequate, given that WebP is now as universal as it ever was.

```html
<picture>
  <source srcset="image.avif" type="image/avif">
  <img src="image.jpg" alt="Description">
</picture>
```

## AVIF vs. WebP: which to choose in 2026

| Consideration | AVIF | WebP |
|---------------|------|------|
| Compression (photos) | ~50–80% smaller than JPEG | ~25–35% smaller than JPEG |
| Compression (vs. each other) | 10–20% smaller than WebP | — |
| Browser coverage | ~93–95% | ~97%+ |
| Encoding speed | Slow (CPU-intensive) | Fast |
| Decoding speed | Fast | Fast |
| Transparency | Yes | Yes |
| Animation | Yes (see note below) | Yes |

**Animated AVIF** is supported by most browsers that also support still AVIF images. However, some external platforms may not yet support animated AVIF. **Slack previews, GitHub comments, and most email clients will expect GIF images instead of AVIF images.** [Convert the AVIF images to GIF in your browser](/avif-to-gif/) first if you need to upload them to those destinations.

**Choose AVIF when:**
- **File size reduction is the priority** (image-heavy pages, e-commerce)
- You're starting a new project and can implement proper fallbacks
- Your users are predominantly on modern devices (mobile-first audience skews newer)

**Stick with WebP when:**
- Your already working WebP implementation has higher costs for a migration than the savings for a new image format.
- **Dynamic image generation** (AVIF encoding is 5–10x slower than WebP)
- Support a large number of older iOS users.

## Does AVIF work on mobile?

Safari on iOS started supporting AVIF with **iOS 16.4 (March 2023)**. Chrome on Android started supporting it with **Chrome 85 (2020)**. The main mobile edge case here is older iPhones that cannot upgrade from iOS 15 anymore. Those are running Safari 15, which does not support AVIF yet.

If your analytics indicate that you have a large audience of iOS 15 users (i.e., they are running with older device cycles), it's prudent to continue to include **WebP in your fallback list**.

## AVIF in Next.js and image CDNs

**Next.js Image component:** Next.js can serve AVIF images to support AVIF by specifying `formats: ['image/avif', 'image/webp']` in `next.config.js` within the `<Image>` component. This is opt-in and works out of the box.

**Cloudflare Images, Cloudinary, and Imgix** all support AVIF delivery and automatically negotiate the best format to send to a user's browser. They will send AVIF images that a browser supports and fall back to JPEG or WebP for browsers that do not support AVIF.

**Self-hosted:** When serving images from your own server, you can check for the `image/avif` `Accept` header and send the appropriate image format. **Sharp** is a popular encoding library for AVIF images and is written for Node.js.
