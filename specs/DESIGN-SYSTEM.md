# Design System

This file defines the templated system. Everything on ConvertYard is
built from three layers: **tokens**, **components**, and **content
configs**. Get these right and every new tool is a 1-hour ship.

## Layer 1: Design tokens

All defined as CSS variables in `globals.css` and mirrored in the
Tailwind theme. Change once, propagates everywhere.

### Typography

```css
--font-sans: 'Geist', 'Inter', system-ui, -apple-system, sans-serif;
--font-mono: 'Geist Mono', 'JetBrains Mono', ui-monospace, monospace;

/* Scale */
--text-xs: 0.75rem;    /* 12px */
--text-sm: 0.875rem;   /* 14px */
--text-base: 1rem;     /* 16px */
--text-lg: 1.125rem;   /* 18px */
--text-xl: 1.25rem;    /* 20px */
--text-2xl: 1.5rem;    /* 24px */
--text-3xl: 1.875rem;  /* 30px */
--text-4xl: 2.25rem;   /* 36px */
--text-5xl: 3rem;      /* 48px */

/* Line heights */
--leading-tight: 1.2;
--leading-normal: 1.5;
--leading-relaxed: 1.65;
```

Fonts loaded via `next/font/local` for zero layout shift. System
fonts as fallback — page renders text immediately, brand font swaps
in when ready (`font-display: optional` for non-critical use).

### Spacing

Standard Tailwind 4px scale. Use 4, 8, 12, 16, 24, 32, 48, 64, 96, 128
as primary spacing values. Avoid arbitrary values.

### Radius

```css
--radius-sm: 6px;
--radius-md: 8px;
--radius-lg: 12px;
--radius-xl: 16px;
--radius-full: 9999px;
```

Tool cards and buttons use `--radius-lg`. Pills and badges use
`--radius-full`. Containers and modals use `--radius-xl`.

### Shadows

```css
--shadow-sm: 0 1px 2px 0 rgb(0 0 0 / 0.05);
--shadow-md: 0 4px 6px -1px rgb(0 0 0 / 0.1);
--shadow-lg: 0 10px 15px -3px rgb(0 0 0 / 0.1);
```

Use sparingly. Tool sites should feel solid, not floaty.

### Breakpoints

Tailwind defaults:
- `sm: 640px` (large phone landscape)
- `md: 768px` (tablet)
- `lg: 1024px` (small laptop)
- `xl: 1280px` (desktop)
- `2xl: 1536px` (large desktop)

**Design mobile-first at 375px**, then scale up. Tool sites have
~60% mobile traffic.

## Layer 2: Components

Build these once. Every page composes from them.

### Core layout components

**`<SiteShell>`** — wraps every page. Includes:
- Nav (sticky, top)
- Children (page content)
- Footer
- Skip-to-content link

**`<Nav>`** — site navigation. Sticky, slim (~64px), semi-transparent
backdrop with blur. Logo left, menu items right. Mobile hamburger.

**`<Footer>`** — 4-column footer with tool categories, resources,
company, legal. Bottom strip with tagline.

### Tool components

**`<ToolShell>`** — the most important component. Wraps every tool
page. Props:

```typescript
interface ToolShellProps {
  config: ToolConfig;
}

interface ToolConfig {
  slug: string;
  title: string;
  subtitle: string;
  category: 'images' | 'pdf' | 'video-audio' | 'dev' | 'web' | 'ai';
  accepts: string[];           // MIME types
  acceptsExt: string[];        // file extensions for display
  outputExt: string;
  convertFn: (files: File[], options: any) => Promise<File[]>;
  options?: ToolOption[];      // sliders, toggles, dropdowns
  faq: FAQItem[];
  relatedTools: string[];      // slugs of 3-5 related tools
  relatedArticles: string[];   // slugs of 2-3 articles
  meta: {
    title: string;             // SEO title
    description: string;       // 140-155 chars
    ogImage?: string;          // generated by default
  };
}
```

Renders:
- Page H1 + subtitle (always: "Local-first [task]. Built for batches.")
- Dropzone with batch progress
- Options panel (if provided)
- Convert button
- Result list with download all / individual
- "How this tool works" mini-explainer
- FAQ accordion
- Related tools strip
- Related articles strip
- All SEO metadata + schema

**`<Dropzone>`** — handles drag-drop + click-to-pick + paste.
- Visual states: idle, drag-over, drop-error, processing, done
- Accessibility: keyboard accessible, screen reader announces files added
- Mobile: tap to open file picker
- Shows file count, total size, "add more files" button

**`<ProgressList>`** — per-file progress during conversion.
- Filename, size, progress bar, status icon
- Virtualized when >50 files

**`<OptionsPanel>`** — renders tool-specific options from schema.
Supports: slider, toggle, dropdown, radio group, number input.

### Article components

**`<ArticleShell>`** — wraps every article page.
- H1, byline, last-updated date
- Table of contents (auto-generated from H2s)
- MDX content with custom components
- Related tools widget
- FAQ section with schema (if article has FAQs)

### UI primitives

- `<Button>` — primary, secondary, ghost; sm/md/lg sizes
- `<Card>` — base for tool cards, comparison rows, FAQ items
- `<Badge>` — for category tags, "New", "Local", "Batch"
- `<Tabs>` — for category filter, options panels
- `<Accordion>` — for FAQ
- `<Tooltip>` — for option hints
- `<Toast>` — for ephemeral feedback (file added, copied, etc.)

All built on Radix UI primitives for accessibility, styled with Tailwind.

## Layer 3: Content configs

Every tool is a config object. Example:

```typescript
// /content/tools/jpg-to-webp.ts
import { libvipsConvert } from '@/lib/converters/libvips';
import type { ToolConfig } from '@/lib/types';

export const config: ToolConfig = {
  slug: 'jpg-to-webp',
  title: 'JPG to WebP Converter',
  subtitle: 'Local-first JPG to WebP conversion. Built for batches.',
  category: 'images',
  accepts: ['image/jpeg'],
  acceptsExt: ['.jpg', '.jpeg'],
  outputExt: '.webp',
  convertFn: (files, opts) => libvipsConvert(files, 'webp', opts),
  options: [
    {
      type: 'slider',
      name: 'quality',
      label: 'Quality',
      min: 1, max: 100, default: 80,
      hint: '80 is the sweet spot for most uses',
    },
    {
      type: 'toggle',
      name: 'lossless',
      label: 'Lossless mode',
      default: false,
      hint: 'Larger files, perfect quality',
    },
  ],
  faq: [
    { q: 'Will quality drop?', a: '...' },
    { q: 'Maximum file size?', a: '...' },
    // 4-8 entries
  ],
  relatedTools: ['png-to-webp', 'jpg-to-avif', 'webp-to-jpg'],
  relatedArticles: ['webp-vs-avif-vs-jpeg', 'best-webp-quality'],
  meta: {
    title: 'JPG to WebP Converter — ConvertYard',
    description: 'Convert JPG to WebP locally in your browser. Batch up to 1,000 files. No uploads, no signups, no watermarks.',
  },
};
```

The page itself:

```typescript
// /app/(tools)/jpg-to-webp/page.tsx
import { ToolShell } from '@/components/tool-shell';
import { config } from '@/content/tools/jpg-to-webp';

export const metadata = config.meta;
export default function Page() {
  return <ToolShell config={config} />;
}
```

**That's the whole new-tool workflow.** Write a config, write a
converter function, ship.

## Adding a new tool (checklist)

1. Read the relevant `/categories/*.md` cluster brief
2. Create `/content/tools/{slug}.ts` with full config
3. Implement converter function in `/lib/converters/` (or reuse)
4. Create `/app/(tools)/{slug}/page.tsx` (5 lines)
5. Add slug to relevant category page's tool list
6. Test with 1, 10, 100, 1000 files
7. Test on mobile (375px viewport at minimum)
8. Test with keyboard navigation
9. Verify FAQ schema renders in Rich Results Test
10. Draft 3 supporting articles (can ship after tool)

If any of the above takes more than a few minutes, the shell is doing
too little — fix the shell, not the tool.

## Adding a new component (rules)

- Lives in `/components`
- Has TypeScript props interface
- Has a `*.stories.tsx` file (Storybook or Ladle) for visual regression
- Built on Radix UI when accessibility matters (menus, dialogs, tabs)
- No inline styles; Tailwind classes only
- Mobile-tested at 375px before commit

## Adding a new category (rare)

If you ever add an 8th cluster:
1. Add to `/content/categories.ts`
2. Update `Nav` megamenu
3. Update `Footer` columns
4. Add hub page at `/app/(categories)/{slug}/page.tsx`
5. Create `/categories/08-{name}.md` cluster brief
6. Update homepage tool grid filter pills
